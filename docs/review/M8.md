## Summary

The design is careful and largely verified: prediction, glue validity, self data and `.bcf`
citekey counts all have verification steps or fallbacks. The layering is clean (no upward
imports). Unit tests are fast (124 tests in 1.7 s).

The main risks for a public 0.9 are four **silent stale-output paths**:

1. Local files loaded in the format part (class, `.sty`, `.cfg`) are not covered by the format
   stamp (C1).
2. List-file extensions are hard-coded, e.g. `.loa`/`.loe` are not handled (C2).
3. Files read inside cached pictures are not part of the picture key (C3).
4. TeX distribution updates and fastinc upgrades do not force a cold build (C4).

`fastinc check` would not detect (C3), because its reference reuses the persistent picture cache
(C5).

Robustness is also weak against **concurrent or killed processes**: there is no lock, canon
writes are not atomic, and child processes can be orphaned (C6–C8).

**Decisions (user, 2026-11-03):**
- `check` keeps exit code 1 on a difference (the current behaviour, PLAN F10).
- PLAN Appendix A and `tests/corpus/thesis/preamble.tex` contain nothing sensitive and stay.
- Target name **`latex-chapmk`** (repository and PyPI); command, Python package, `.sty` files and macro prefix `chapmk` (R6). Renaming is a dedicated step: R13, 5.2.
- IDs, file names and line numbers in this review refer to the `fastinc` names at `ecbfb44`.

### 2.1 Design assessment

**Keep:**
- Pure modules with high unit coverage: `predict` (100 %), `texsource`, `aux`, `tools`, `deps`, `synctex`, `lint`.
- `texdist` as the only place with engine flags; `proc` as the only subprocess path.
- `Layout` for all paths; the `publish` writer abstraction; a frozen `Config`.
- Accurate module maps; clean layering.

**Weak points:**
- **Orchestration concentrated in one module.** `incremental.py` has 1001 lines and 15 % unit coverage; it holds the dirty rules, planning, prediction, commit, verification, pictures and reporting (E1).
- **State mutation without an owner.** `State` is changed in place in `canon.py` (5 sites) and `incremental.py` (7 sites). It is written by `save_state` only after the whole batch, so the canon files run ahead of `state.json` (C7).
- **Fallback triggers spread over many exception types.** `RecordError`, `ToolInputError`, `MergeError`/`MergeFailedError`, a format `TexError` and `FallbackError` are converted at five sites: `incremental.py:222,653,674,939`, `outputs.py:98`. Errors outside this set give a traceback (C9).
- **Document facts duplicated.** List suffixes, chapter-level headings and unsupported packages are each defined in several modules and in `fastinc.sty` (C2, E2).
- **No single run object.** The records of a run are parsed in `incremental` and again in `outputs.publish_state` (`outputs.py:70`). The `.fls` is parsed in `fullbuild.read_inputs` and again in `incremental._check_runtime_support`.

### 4.1 Editor recipes (to verify and put into the README)

- **VS Code, LaTeX Workshop:** tool `{"name": "fastinc", "command": "fastinc", "args": ["build", "%DOCFILE_EXT%"]}`, recipe `{"name": "fastinc", "tools": ["fastinc"]}`. Forward and inverse search use `main.synctex.gz` next to the PDF (paths already mapped to the sources). Build on save runs often: needs C6/C8. Problems panel: LaTeX Workshop parses the build output and log; check that the mapped `file:line:` first error (stderr) and the published `main.log` are picked up.
- **TeXstudio:** Options → Build → user command `fastinc build %.tex`; set it as the default compiler. The internal viewer uses `%.synctex.gz`; the log parser reads `%.log` (published, mapped).
- **vimtex:** `g:vimtex_compiler_method = 'generic'` with `g:vimtex_compiler_generic = {'command': 'fastinc build main.tex'}` (or a watcher such as `entr` until `watch` exists). Viewers (zathura, Skim, sioyek, SumatraPDF) do forward/inverse search via `synctex`; the `<src>/./file.tex` form is kept (S10).
- Generic: `synctex view -i LINE:COL:FILE -o main.pdf` works across the merged PDF (F4, T17).

### 4.2 User-facing limitations (for the README)

1. pdfLaTeX only; TeX Live only (MiKTeX in M9); Windows not tested yet.
2. Units are top-level `\include`s of the main file; an include without a chapter-level heading joins the preceding unit; `\include` arguments without spaces, `..` or absolute paths.
3. Unit bodies must not change macros or lengths outside groups (A1). Lint warns, and such a unit is then compiled in every run.
4. Edits of the main-file body, the include list, global inputs or a `.bib` file trigger a cold build (U8).
5. Full mode (like latexmk, reason printed): `glossaries`, `imakeidx`/`makeidx`, `minted`, `cleveref`, BibTeX or a biblatex backend ≠ biber, hyperref without `bookmark`, `\begin{document}` not in the main file, `\include` in a group, `\documentclass` on the split line, citations in a refsection ≠ 0, format-build failure, no fixpoint, merge failure.
6. Sources outside the main file's directory (`../`) are not found.
7. TikZ externalize: figures are made by fastinc (no shell escape); results equal an externalized build, not an inline one; references hidden in macros are not tracked.
8. Label/cite keys built by macros are not tracked (run `fastinc check` if in doubt).
9. eqparbox tags shared by several units (C13); files that appear only later via `\IfFileExists` are not noticed.
10. `\today` and the PDF dates are fixed at the cold build (U7). The merged PDF is larger (fonts per run); use `--full` for the final version.
11. fastinc uses one of TeX's 16 write streams (`\newwrite` in `fastinc.sty:76`).

### 5.1 Platform assumptions to collect for M9
