# S17: mparhack and acronym

**Question.** In the corpus sweep, a thesis based on classicthesis (which loads `mparhack` and
`acronym`) recompiled all units on every typo: their aux statements were unclassified
(design §6.7.2), and a change of unclassified data dirties everything. Can they be
classified, and is the output then still correct?

**Setup.** TeX Live 2026, dev image. `tests/corpus/minimal/S17-mparhack-acronym/`:
`mparhack/` (`book`, twoside, three units with six margin notes each) and `acronym/` (a unit
with the acronym list, then three units using `\ac{AI}` and `\ac{ML}`; the first use prints
the long form). Each step builds with `--check`, `-j 1` and `-j 4`, with the driver patched
to classify the statements as self data.

## Results

**mparhack** writes, per shipped page, `\mph@setcol{ii:<page>}{\mph@nr}` with the
document-wide number of the last margin note so far (`\mph@cnt`, a macro), per note
`\def\mph@nr{<n>}`, and at the end `\gdef\mph@lastpage{<n>}` and
`\csname mph@do@warn\endcsname`. The next run compares its own count with the records of the
page to find the side of a note. A run that excludes earlier units counts from a different
start, but it compares only with the records it wrote itself once its self data is stable
(design §6.8.1 item 5): cold build, three notes added to the first unit, typos in later units
compile only the edited unit, and every step passes §3.3, sequentially and in parallel. Notes
in glue between `\include`s would change the glue's records with the run configuration (not
tested; rare).

**acronym** writes `\acronymused{<key>}` per use, `\AC@undonewlabel` and
`\AC@reset@newl@bel` (its own labels). The first use of an acronym is recorded in a global
macro `\AC@<key>` that is not written to the aux file and is not in the state vector. With the
statements classified, a typo in the second unit compiled only that unit, which printed
"Artificial Intelligence (AI)" again where the full build prints "AI" (§3.3 fails). Without
classification the result was only right because some unclassified statement happened to
change; a typo that leaves them unchanged gives the same wrong output.

## Consequence

`auxfile`: the mparhack statements are self data (`SELF`). `acronym` is added to
`facts.UNSUPPORTED_PACKAGES` (full builds with a warning); carrying its first-use state into
runs would need package-specific restore code in chapmk.sty (also for `\acreset`,
`\acresetall`). The warning about unclassified aux data now names the commands also when
only the order or the number of repeated statements changed (it printed `()`). Design §1,
§6.7.2. Scenario tests `test_mparhack_margin_notes` (`-j 1`, `-j 4`) and
`test_acronym_gives_full_builds`.
