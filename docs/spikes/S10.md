# S10 — SyncTeX merge prototype

**Setup.** TeX Live 2026 (SyncTeX 1), dev image. Reproducer: `tests/corpus/minimal/S10-synctex/` (`./run.sh OUT [badcount]`).
- Document, probe and PDF merge come from S9 (`../S9-merge`); all runs use `-synctex=1`.
- Partial runs: A = `{u1}` (supplies the glue), B = `{u2,u3}`.
- `merge_synctex.py` merges the two `main.synctex.gz` files following the merged page order.
- `verify.py` runs, for every line of `main.tex`, `u1.tex`, `u2.tex` and `u3.tex` that has a SyncTeX record, `synctex view` on both PDFs and `synctex edit` at the first result's position, and compares the outputs with the full run.

**File format** (observed)
- Header: `SyncTeX Version:1`, `Input:<tag>:<path>`, then `Output:pdf`, `Magnification:1000`, `Unit:1`, `X Offset:0`, `Y Offset:0`, `Content:`.
- `Input:` lines also occur mid-content.
- Per page: `{<sheet>` … `}<sheet>`. Records carrying a tag look like `<type><tag>,<line>:…` with types `[ ( h g k x $ v r`; `] )` carry no tag.
- `!<n>` appears before every `{n`, every `}n` and the postamble; `n` = bytes from the previous `!` line (or the file start) to this line (verified on the run files).
- Postamble: `Postamble:`, `Count:<n>`, `!<n>`, `Post scriptum:`.
- **Paths are written as `<absolute cwd>/./<relative path>`.** `synctex view -i line:col:<relative name>` matches files by the part after `/./`. Normalising `/./` away breaks forward search: 0/25 in the first attempt.

**Merge (prototype)**
1. Parse each run: tag → path, header values, sheets.
2. Global input table keyed by path, keeping the original `/./` form. Rewrite the tags of every tagged record.
3. Take the sheets of the merged pages in order, renumber them, recompute all `!` offsets and the postamble.
4. The header values must be equal across runs, otherwise error.

**Result**

| Check | Result |
|---|---|
| `synctex view` for all 25 source lines with records (glue in `main.tex`, all units) | 25/25 identical to the full run (page, x, y, h, v, W, H) |
| `synctex edit` at those positions | 25/25 identical (file, line) |
| negative control: run A alone vs full run | 16/25, FAIL |
| `Count:` deliberately wrong (`Count:1`) | still 25/25: the `synctex` tool does not validate `Count` |

**Consequences for the plan (§6.12)**
- Keep the path form `<cwd>/./<relative>`. Path mapping replaces only the cwd prefix: shadow tree → source directory (S2). Do not normalise `/./`; this corrects S2's "normalise `/./`".
- `Count` is not checked by the tool. It is still computed (number of tagged and box records); its exact semantics are irrelevant for viewers.
- `!` offsets: bytes since the previous `!` line.
