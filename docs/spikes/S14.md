# S14: aux records of an exported picture's extra page

**Question.** A real document's log showed `LaTeX Warning: Label `pgfid1' multiply defined`,
read from a canonical unit aux. `pgfid1` is TikZ's position record of a `remember picture`
picture. Does the picture cache's extra page (§6.17: a copy of the picture box shipped with the
primitive `\shipout`) write the picture's records a second time? How can the copy's records be
kept out of the aux file without changing the picture?

**Setup.** TeX Live 2026 (pdfTeX 1.40.29), `texlive/texlive:latest`.
`tests/corpus/minimal/S14-picture-records/`:
- `mechanism.tex`: without chapmk. A box with a `remember picture` node holding a `\label` is
  shipped as an extra page (`\copy`, primitive `\shipout`) and then typeset in the document.
  With `\def\useskip{}`, immediate writes of `\chapmk@picskip` / `\chapmk@picskipend` enclose
  the extra shipout, and `\long\def\chapmk@picskip#1\chapmk@picskipend{}` is defined.
- `main.tex`, `u1.tex`, `u2.tex`, `run.sh`: the same with chapmk (an externalized `remember
  picture` picture and a `\label` in a node, in an `\include`); used by the scenario test.

## Results

`mechanism.tex`, four runs each:

| | aux after run 1 | second run's log | stable |
|---|---|---|---|
| plain | `\newlabel{pic:node}` and `\pgfsyspdfmark {pgfid1}` twice: first the copy's (extra page position), then the document's | `Label `pic:node' multiply defined`, `Label `pgfid1' multiply defined`, every run | from run 3 |
| skip markers | the copy's records between `\chapmk@picskip` and `\chapmk@picskipend` | no warning | from run 3 |

- Every delayed write in the box (`\protected@write`: `\label`, TikZ's `\pgfsyspdfmark`) is
  executed at each shipout of the box, so the copy writes the records again. The text was
  expanded when the box was built, so redefining macros at the extra shipout cannot suppress
  them; TeX has no way to drop whatsits from a box.
- Without the markers the first definition wins: the document used the copy's position, i.e.
  the position on the extra page, for `remember picture`.
- With the markers TeX gobbles the copy's records when it reads the aux file; labels and
  positions are the document's, as without chapmk.

With chapmk (dev image, TeX Live 2026; `u1.tex` variants, code of `main` without any fix):

| Externalized picture in an `\include` | Incremental build (cold, then an edit of `u2`) | `--full` |
|---|---|---|
| `\tikz[remember picture]` (and further pictures) | no warning in the published log, no duplicate `pgfid` record in the canonical aux | finishes |
| `\node{… \label{pic:node}}` | no warning | **no fixpoint after 8 passes**: the exporting pass writes the label, the embedding pass does not; the full-mode key digests all label values, so the keys change and the picture is exported again (period 3) |

- TikZ writes the `remember picture` records to `\@mainaux`, also inside an `\include`.
- The picture typeset inline for export writes its records too, not only the copy, and the
  register restore after it resets TikZ's picture counter (as with real externalize, where the
  main job does not run cached pictures). Markers around the extra page cannot remove them.
- With real externalize such a picture's records end up in the figure job's aux: the main
  document loses the label (`??`) or the position.

## Consequence

Decision (user): pictures with more side effects than the cache supports are not
externalized.
- `chapmk-ini.sty`: a picture whose code contains `remember picture` or `\label` is typeset
  inline, never exported, as with `\tikzexternaldisable`, and `Package chapmk Warning` names
  its input line. Incremental and full builds then agree, `--full` converges, nothing is
  written twice.
- The output differs from latexmk with real externalize for such pictures (labels and
  positions are kept instead of lost); accepted (§6.17).
- Not detected: `remember picture` set globally (`\tikzset{every picture/.style=…}`) and
  labels in macros the picture calls.
- The skip markers around the extra page (first attempt) are not needed and were dropped.
