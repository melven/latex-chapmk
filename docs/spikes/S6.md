# S6 — hyperref destinations, dummies, duplicates, anchors; bookmark records

**Setup.** TeX Live 2026 (hyperref 7.01s, bookmark 1.32), dev image. Reproducer: `tests/corpus/minimal/S6-hyperref/` (`./run.sh OUT`, `inspect.py` prints the destinations, outline, links and page labels).
- Test document: `scrbook`, twoside, hyperref (scrbook loads `bookmark`), `\maketitle` (title page), `\frontmatter` with ToC, `\mainmatter`.
- Units: u1 (chapter, section, `\section*`, subsection, footnote, link to u3); u2 (chapter, `\ref`, `\autoref`, `\nameref`, `\pageref` to u1/u3, `\url`, `\section*`); u3 (chapter, section, link to u1).
- Runs: converged full build; one pass with `\includeonly{u2}` (no fastinc restore).

**Results**

1. **Named destinations.**
   - `/Root/Names/Dests` is a name tree with `/Kids` and `/Limits`.
   - Values are dictionaries `<< /D [<page> /XYZ x y null] >>`.
   - Links are `/A << /S /GoTo /D (<name>) >>` or `/S /URI`.
   - The outline uses `/A` GoTo actions with names.
2. **Dummy destinations** (partial run, targets in excluded units):
   - log `pdfTeX warning (dest): name{section.1.1} has been referenced but does not exist, replaced by a fixed one`;
   - the PDF has `<< /D [<page 0> /Fit] >>` for that name.
3. **Duplicates also occur in the full run.**
   - Log: `pdfTeX warning (ext4): destination with the same identifier (name{page.1}) has been already used, duplicate ignored`. Here `page.1` and `page.2` come from the title pages, which are numbered 1, 2 before `\frontmatter`; the main matter repeats 1, 2.
   - The first definition wins: `page.1` → title page.
   - This confirms the merge rule (first in document order wins; PLAN §6.11).
4. **Anchors.**
   - `section*.N` is numbered by `\Hy@linkcounter`: full run `section*.1` (u1), `section*.2` (u2).
   - The partial run without restore names u2's anchor `section*.1`, which collides with u1's at the merge. The register restore (S4) prevents this.
   - Other names: `chapter.N`, `section.N.M`, `subsection.…`, `Hfootnote.N`, `page.<\thepage>`, `Doc-Start`.
5. **`\HyPL@Entry`** does not occur (TL 2026 hyperref writes `/PageLabels` itself). Page labels are consistent between runs; the merge builds them from the page map anyway (§6.11).
6. **Blank pages from `\cleardoubleoddpage`** before a chapter are shipped after `include/before` of that chapter's unit, so they belong to the following unit. This is consistent between full and partial runs (u2 = blank page 2 + chapter page 3 in both).
7. **`bookmark` records** (`bkm-pdftex.def`):
   - `\BKM@entry{id=N[,open][,dest={hex}][,named=…][,uri=…][,color=…][,flags=…][,srcline={L}]}{<hex title>}` is written by `\immediate\write\@mainaux` to the **main aux**, not the unit aux. A partial run contains only its included units' entries, so per-segment main-aux slices are needed, as in S5.
   - `title` is hex-encoded PDF string bytes (here UTF-16BE with BOM, as octal escapes). `dest` is the hex-encoded name.
   - **Level and parent are not in the aux.** They live in the run-internal macros `\BKM@<id>` = `{parent}{level}{children}`; `\pdfoutline` takes the child count from there.
   - `open` is computed against `openlevel` at write time. `\section*` produces no bookmark.
   - No `.out` file is written.

**Consequences for the plan**
- §4 / §6.7.2: `\BKM@entry` lines are in the **main aux**, attributed by segment slices (§6.6).
- §6.4.2: new record. At `enddocument`, write `\fastinc@bkmlevels{<id>=<level>,…}` from the `\BKM@<id>` macros to the main aux. The merge rebuilds the tree from the levels, using bookmark's rule (parent = nearest previous entry with a lower level). Run-local ids are mapped per run.
- §6.11.2: dummy destinations are recognised by the log warning (`/Fit` on page 0 as a cross-check). Destination values are `<< /D [...] >>` dictionaries.
- §6.7.2: drop `\HyPL@Entry`.
