# S5 — biblatex `.bcf` after `\includeonly` runs

**Setup.** TeX Live 2026, biblatex numeric, biber 2.22. Reproducer: `tests/corpus/minimal/S5-bcf/` (`./run.sh OUT`).
- Glue cites `c`.
- u1: `\cite{b}`, `\cite{a,d}`.
- u2: `\cite{b}` again, `\nocite{e}`.
- u3: `\cite{f}`.
- Runs: a converged full build, then single passes with `\includeonly` = `{u1}`, `{u2}`, `{u3}`, `{}` and `{u1,u3}`. No fastinc register restore.

**Results**

| Run | `bcf:citekey` elements (key(order.intorder)) |
|---|---|
| full | c(1.1) b(2.1) a(3.1) d(3.2) b(4.1) e(5.1, nocite) f(6.1) |
| `{u1}` | c(1.1) b(2.1) a(3.1) d(3.2) |
| `{u2}` | c(1.1) b(2.1) e(3.1, nocite) |
| `{u3}` | c(1.1) f(2.1) |
| `{}` | c(1.1) |
| `{u1,u3}` | c(1.1) b(2.1) a(3.1) d(3.2) f(4.1) |

1. **A partial run's `.bcf` contains only the citations of the glue and the included units.** Biber on it would drop the other entries from the `.bbl`, so **`.bcf` patching is needed** (decision point).
2. Apart from the `bcf:citekey` elements, the `.bcf` of a partial run is identical to the full run's.
3. There is one citekey element per key per citation command:
   - `order` is the command counter (`blx@sectionciteorder@<section>`, restored by the fastinc register restore, S4);
   - `intorder` is the position within the command;
   - `\nocite` adds `nocite="1"`.
4. **`\abx@aux@cite{<section>}{<key>}` lines are written to the main aux**, not to the unit aux, immediately and in citation order. Their sequence corresponds 1:1 to the citekey elements in the `.bcf` (7 lines ↔ 7 elements).

**Feasibility of the patch.** The fastinc segment records `\fastinc@entry` are also written immediately to the main aux. They split the `\abx@aux@cite` lines into per-segment slices, and the 1:1 correspondence attributes each citekey element of a run to its segment. The canonical citekey list is the concatenation of each segment's elements from the run that committed that segment, in document order, with `order` renumbered globally. `intorder` and `nocite` are kept. This is an XML edit of one element list per `bcf:section`.

**Consequences for the plan**
- §6.7.2: `\abx@aux@cite` (and probably more `\abx@aux@*` lines) are in the **main aux**, which therefore has per-segment content. The canonical main aux must be assembled from per-segment slices (delimited by the immediate `\fastinc@entry` records). S8 inventories the remaining main-aux lines.
- §6.10: `.bcf` patching as described above, or the alternative chosen at the decision point.
