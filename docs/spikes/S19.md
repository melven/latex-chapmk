# S19: state a unit leaves for the glue after it (carried state)

**Question.** Sweep category C1 (issue #78): in three documents a ToC entry or bookmark
after the last `\include` points to the wrong page. Which state causes it, and does a restore
at the excluded unit's checkpoint give the full build's result?

**Setup.** TeX Live 2026, dev image. `tests/corpus/minimal/S19-carried-state/` (`scrbook`
with `listof=totoc`, hyperref, bookmark, three units with sections and a figure). After the
last `\include`: `\listoffigures` (KOMA adds its ToC entry with `\addcontentsline`), then
`\addcontentsline{toc}{chapter}{REFERENCES}`, `\label{refs}`, `\ref{refs}` and
`\nameref{refs}`. Cold build with `--check` (its parallel batch excludes `c`), then edits.

## Results

On `main`, the cold build already fails `--check` (page 10 of 11): in the run that excludes
`c`, the LoF's ToC link and bookmark point to page 1 (`Doc-Start`) instead of page 8,
`\ref{refs}` is empty instead of `3.2`, and `\nameref{refs}` is empty instead of "Last of c".
`\addcontentsline` (hyperref) takes its target from `\@currentHref`, `\label` its text from
`\@currentlabel`, its type from `\@currentcounter` and nameref's title from
`\@currentlabelname`. The last unit leaves all four; no checkpoint carries them.

These macros are set locally (`\edef`) by `\refstepcounter` and hyperref's anchors, so a
float or environment does not change them for the following text: the value at the end of a
unit is the last one set outside every group. `\include` adds no group.

Prototype: `chapmk.sty` records the four macros at each unit's end (`\chapmk@cv{<id>}{<text>}`
in the unit aux) and an excluded unit's checkpoint restores them with `\gdef`, like the
running-head marks. Each is a pseudo register of the state vector (digest of the text after
an aux round trip).

| Build | Compiled | `--check` |
|---|---|---|
| cold (`-j 4` and `-j 1`) | all, then glue-only runs (as on `main`) | pass |
| typo in `a` / in `c` | `a` / `c` | pass |
| new last section in `b` | `b`, then `c` (entry state: marks and `\@currentHref`) | pass |
| new last section in `c` | `c` | pass |

A changed last section already changed the running-head marks, so it recompiled the next
unit before too. The carried items add a recompile only where a unit's last anchor outside
any group changes without a mark, e.g. a `\phantomsection` at its end.

## Consequence

Design §6.4.2 (carried state: one declaration per item, kind `macro`), Appendix B (`\chapmk@cv`,
`C <id> <kind> <name>`). User decision (issue #78, 1a): no exemption for units whose leading
heading overwrites the items; a changed item at a unit's end recompiles the next unit.
Tests: `test_state_a_unit_leaves_for_the_glue`, `test_contents_line_before_the_bibliography`.
