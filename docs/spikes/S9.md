# S9 — PDF merge prototype (pikepdf)

**Setup.** TeX Live 2026, pikepdf (dev image). Reproducer: `tests/corpus/minimal/S9-merge/` (`./run.sh OUT`).
- Document: the S6 document. scrbook twoside, hyperref and bookmark, a title page producing duplicate `page.1`/`page.2`, ToC, three units with `\section*`, cross-unit links, a footnote and a URL.
- `s9probe.sty` is a minimal prototype of the `fastinc.sty` records:
  - segment tracking with immediate segment markers in the main aux;
  - page map `main.fpg`;
  - register restore for excluded units (S4);
  - bookmark levels (S6).
- Runs: converged full build (reference). From its aux, partial runs A = `{u1}` and B = `{u2,u3}`.
- `merge.py` merges: glue and u1 from A, u2 and u3 from B. `compare.py` checks §3.3 items 1–3 against the full run.

**Merge steps (prototype)**
1. **Pages** of each segment from its run (page map), appended in segment order (pikepdf foreign copy; annotations come with the pages).
2. **Named destinations** of each run whose target page was taken from that run, minus dummies (log), first in merged page order wins. They are written into a new `/Names /Dests` tree with the target remapped.
3. **Outline**:
   - `\BKM@entry` records of each segment's main-aux slice in its run, levels from the run's level record;
   - title: hex → TeX octal escapes → PDF string bytes;
   - tree rebuilt (parent = nearest previous entry with a lower level), `/Count` from the `open` key.
4. **Page labels** from the page map (`\c@page`, `\thepage`): style inference `/D`, `/r`, `/R`, otherwise a prefix label; new range at a style change or a non-consecutive value.
5. **Catalog and Info** from the run that supplied G0.

**Result**

| §3.3 item | Result |
|---|---|
| page count (9) | identical |
| raster, `pdftoppm -r 150`, every page | identical |
| text, `pdftotext -layout`, per page | identical |
| page labels (`1 2 i ii 1 2 3 4 5`) | identical |
| outline (titles, levels, `/Count`, resolved target page and coordinates) | identical |
| links (14: rectangle, resolved target page and coordinates, URI) | identical |

- Duplicate `page.1` resolves to the title page, as in the full run.
- `section*.2` resolves to u2's page. This needs the register restore; without it the anchor would be `section*.1`, see S6.
- **Negative control:** comparing run A alone with the full run fails (dummy destination `/Fit` on page 0), so the comparison is not vacuous.

**Consequences for the plan**
- The approach of §6.11 works as specified with the S6 adjustments (bookmark records plus levels, dummies from the log, first-wins duplicates).
- `compare.py` is the basis for `fastinc check` and for the acceptance tests.
- Not covered yet: direct page-object destinations (none occur with hyperref), `/OpenAction` (not set here), multiple duplicate names across runs, alphabetic page labels.
