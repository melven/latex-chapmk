# S13: pdfTeX state a format does not keep

**Question.** Found under MiKTeX with the old `hgbthesis` (2025/02/24; S11 work):
- math text extraction differed from `--full` (the `cmap` package's ToUnicode CMaps);
- a colour left open across a page break was lost.

Which pdfTeX state set in the format part (before the split point, §6.3) is lost by the dump? How can chapmk detect it? Should it restore the state, split before it, or fall back?

**Setup.** TeX Live 2026 (pdfTeX 1.40.29) in the dev image. The cases are in `tests/corpus/minimal/S13-format-state/`; `run.sh` builds each with `chapmk build --check`. Further one-off probes covered `\pdfcatalog`, `\pdfinfo`, `\pdfglyphtounicode` and `\pdfmapline`.

## Results

| State set before the split point | After the dump | Effect | Seen by |
|---|---|---|---|
| `\immediate\pdfobj` (e.g. `cmap`'s ToUnicode streams, which `\pdffontattr` refers to) | Discarded. The format log says `pdfTeX warning: … dangling objects discarded, no output file produced` | Fonts refer to a CMap that does not exist; text extraction differs (`x` instead of `𝑥`) | `check` (text) |
| Colour stacks (`\pdfcolorstackinit`) | Lost; only the built-in stack 0 exists at runtime | TeX error `Unknown color stack number 1` (or, with older drivers, colour lost after a page break) | the run fails |
| `\pdfcatalog{…}` (e.g. `/PageMode`) | Lost | Entry missing in the PDF | **nothing**: §3.3 does not compare the catalog |
| `\pdfinfo{…}` (e.g. `/Keywords`) | Lost | Entry missing in the PDF | **nothing**: §3.3 does not compare the document info |
| `\pdfglyphtounicode` (`\input{glyphtounicode}`) | Kept | none | – |
| `\pdfmapline` | Kept | none | – |
| Form xobjects, images | Lost | Already rejected (`chapmk-pdf-objects`, §6.3.2) | format build |

The colour driver of TeX Live 2026 uses only stack 0, so `xcolor` itself is not affected (case `colorstack-driver`: PASS). Older drivers that call `\pdfcolorstackinit` while loading are affected, as is any package that creates its own stack in the preamble. That is the MiKTeX case.

## Detection

All in the format build, at no extra cost:
- **Immediate objects:** the format log contains `dangling objects discarded`.
- **Colour stacks:** a probe at the end of the format source, `\the\numexpr\pdfcolorstackinit direct{}\relax`. It returns the next free stack number (it allocates one, which is harmless at dump time). A value above 1 means stacks were created in the format part.
- **`\pdfcatalog`, `\pdfinfo` (and the similar `\pdfnames`, `\pdftrailer`):** these take a general text and no `\immediate` prefix. In format builds, `chapmk-ini.sty` can wrap them, so detection and restore are the same step (option 4 below).

The three corpora (thesis with the user's preamble, hgb, pictures) create 3 objects each in the format part. They are reserved, not written: no dangling-objects warning and no colour stacks. They are unaffected.

## Options

1. **Detect and fall back** (small). Dangling objects or extra colour stacks make the format unusable, like form xobjects today: full build with a message naming the reason and `format.split_before`. Correct, but every build of an affected document is a full build.
2. **Deny list** (small, with 1). Split before `\usepackage{cmap}` (and other known packages), so documents that load `cmap` themselves stay incremental. It does not help when the class loads `cmap` (the old `hgbthesis`): the split point cannot be before `\documentclass`, so option 1 applies.
3. **Automatic split search** (medium). When the format build reports lost state, bisect the preamble lines between `\documentclass` and the split point (about log₂ n format builds, once; the result is kept in the format stamp) and split before the first line that causes it. This covers every detectable case without configuration, including form xobjects. Fallback only if the class causes it.
4. **Replay `\pdfcatalog`, `\pdfinfo`, `\pdfnames`, `\pdftrailer`** (small). In format builds, `chapmk-ini.sty` wraps them to record their arguments in a macro that is dumped, and replays them at `begindocument/before` of every run. That is an exact restore in the original order. Immediate objects and colour stacks cannot be replayed this way: object numbers and stack numbers are fixed at the time of the dump.
5. **Extend `check`** (small). Compare the document info and the catalog entries (`/PageMode`, `/PageLayout`, `/ViewerPreferences`, `/OpenAction`, …). This makes §3.3 stricter (no weakening); such losses would no longer go unnoticed.

## Consequence for the plan

Pending the user's decision. Recommended: 1 + 2 + 4 + 5 now, which closes all cases found. Option 3 later if a real document needs it.
