# Contributing

Bug reports and pull requests are welcome. For a bug, please use the issue form and include
the output of `chapmk check` and `-v`. Never post private documents, their logs or PDFs.

## Development environment

Everything runs in the dev container (TeX Live full, Python, poppler, synctex):

```
docker build -t chapmk-dev .
docker run --rm -it -v "$PWD":/work -w /work chapmk-dev bash
pip install -e ".[dev]"
```

or open the repository as a devcontainer (`.devcontainer/devcontainer.json`). Behind a
proxy, pass it as build arguments (`--build-arg HTTPS_PROXY=...`, `--network host`); if it
intercepts TLS, add `--secret id=ca,src=<CA bundle including the public CAs>`.

## Checks

```
ruff check . && ruff format --check .
mypy --strict src
pytest -m "not slow"                  # unit tests, no TeX, seconds
pytest -n auto --dist worksteal       # everything, parallel
pytest -m acceptance -n auto          # scenarios compared with a plain full build
```

CI runs all of these, measures branch coverage (floor in `pyproject.toml`) and installs the
built wheel into a clean venv. It runs on pull requests and on `main`, in the dev image from
GHCR (tagged by the hash of `Dockerfile` and `requirements-dev.txt`; built and published when
missing), and restores the reference cache of an earlier run with the same image and
full-mode code.

- Test layout:
  - `tests/unit` (no TeX);
  - `tests/slow` (real TeX runs);
  - `tests/acceptance`;
  - `tests/scenarios`: edit scenarios; each build is compared with `--full` via `--check`;
  - `tests/corpus`: test documents, never built in place.
- Reference builds are cached in `.test-cache/` by a hash of the sources, the TeX
  installation and the full-mode code (`tests/conftest.py`); `rm -rf .test-cache` frees the
  space of unused entries.
- Tests must be xdist-safe: only `tmp_path` and no global state.
- Never weaken, skip or `xfail` a scenario or acceptance test to make it pass.

## Adding a scenario

Write the document in the test (see `tests/scenarios/test_edge_cases.py`), or copy a corpus with
the `copy_corpus` fixture. Build it with `build(src, "--check")` from `_helpers.py`, edit a
source, build again, and assert the mode, the compiled units (`selections`) and the reasons.
The thesis corpus is generated by `tests/corpus/thesis/generate.py`: edit the generator,
rerun it and commit both.

## Code

- Read [`docs/design.md`](docs/design.md) (how chapmk works; `§` numbers in the code refer to
  it), `src/chapmk/CLAUDE.md` (module map, public APIs, layering) and
  `src/chapmk/tex/CLAUDE.md` before adding code. Reuse what is listed there, and update the
  maps in the same commit as an API change.
- Python ≥ 3.11, type hints everywhere, `pathlib`, `subprocess` without shell strings.
- All TeX command lines go through `texdist.py`. Never modify the user's sources: generated
  files belong in the build directory.
- LaTeX packages (`src/chapmk/tex/`): records and hooks only, prefix `\chapmk@`, version
  equal to `chapmk.__version__`.
- Correctness first: every optimisation needs a verification or a fallback to a full build.
- Any change of the meaning of `state.json` bumps `STATE_VERSION`.

## Commits

Small commits, one logical step each. The message starts with the component: `driver:`,
`tex:`, `merge:`, `test:`, `spike:`, `plan:` (specification and documentation), `ci:`.
